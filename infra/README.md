# infra

Terraform for Rebound, in two stacks so that **only hourly-billed resources are created and destroyed each
session**, while backups, images, users and the public URL survive between sessions.

| Stack | What | Lifetime | Cost when idle |
| --- | --- | --- | --- |
| [`foundation/`](foundation) | KMS key; backup bucket (versioned, SSE-KMS, 30-day expiry); Terraform state bucket; ECR repos (immutable tags, scan on push); Cognito team pool; dashboard on S3 + CloudFront; GitHub OIDC CI role; budget alerts; CloudTrail | Apply once, keep | ~$2–3/month |
| [`cluster/`](cluster) | VPC (2 AZs, 1 NAT); EKS 2 × t3.medium with access entries and KMS-encrypted Secrets; AWS Load Balancer Controller + metrics-server (Helm); RDS PostgreSQL 16 (single-AZ, private, managed master secret); IRSA roles for the data jobs and the API | **Each session**, then destroy | $0 after `down.sh` |

```
                 https://<id>.cloudfront.net   (foundation: stable URL, HTTPS)
                   /*  -> S3 dashboard (OAC)
                   /api/*, /apps/*  -> ALB  (cluster: created by the Ingresses)
                                          -> EKS pods: rebound-api, notes-app, notes-app-recovery
                                          -> Jobs: provision / backup / restore  -> RDS (private subnets)
                                                                                  -> S3 backups (KMS)
```

## First time (once, by one person)

```bash
cd infra/foundation
cp terraform.tfvars.example terraform.tfvars   # team emails, budget emails
terraform init && terraform apply
```

Then move the foundation state into the bucket it just created, so teammates can use it:
uncomment `backend "s3" {}` in `foundation/versions.tf`, run `infra/scripts/up.sh` once up to the point where it
writes `infra/backend.hcl` (or write it by hand from `terraform output tfstate_bucket`), and
`terraform init -migrate-state -backend-config=../backend.hcl -backend-config="key=foundation.tfstate"`.

Each teammate: add their IAM ARN to `cluster/terraform.tfvars` → `admin_principal_arns` (whoever applies is added
automatically). Cognito emails everyone in `team_emails` a temporary password.

## Every session

```bash
infra/scripts/up.sh          # ~20-25 min: cluster, images, DBs, notes-app, API, CloudFront, dashboard
# ... work, demo, capture evidence (docs/submission.md) ...
infra/scripts/down.sh        # ~10-15 min: removes the ALB first, then destroys the cluster stack
```

`up.sh` options: `--yes` (no Terraform prompts), `--skip-images`, `--skip-dashboard`. It writes
`jobs/backup-restore/k8s/.env` (git-ignored) so `rebound-data.sh` works right away.

**Always run `down.sh` at the end.** If it fails halfway, re-run it. Check nothing is left with
`aws eks list-clusters`, `aws rds describe-db-instances`, `aws ec2 describe-nat-gateways --filter Name=state,Values=available`.

## Design notes

- **Two stacks** keep the cost of an idle week near zero and make backups outlive the database they came from:
  restoring a backup taken in a previous session into a brand-new RDS instance is a real recovery test.
- **CloudFront in front of the ALB** gives HTTPS without a custom domain, one origin for the dashboard and API
  (no CORS), and a URL that doesn't change between sessions (poster QR code). `up.sh` re-points it at each
  session's ALB.
- **No static AWS keys anywhere**: workloads use IRSA roles scoped to one service account; CI uses GitHub OIDC
  restricted to `main`; the RDS master password is generated by RDS into Secrets Manager.
- **Least privilege**: data jobs can only touch `backups/*`, the KMS key and `rebound/apps/*` secrets; the API can
  only list/read backup metadata; CI can push to our ECR repos and deploy into the `apps` namespace only.
- **Encryption**: S3 (SSE-KMS + TLS-only policy), RDS storage, RDS master secret, Kubernetes Secrets (EKS
  envelope encryption), ECR, CloudTrail logs: all with the one customer-managed key (rotation on).
- Fargate (proposal) was replaced by 2 managed t3.medium nodes: simpler ALB controller/metrics-server setup and
  no per-pod Fargate overhead for short Jobs. See `docs/decisions.md`.
